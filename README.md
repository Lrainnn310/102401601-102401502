# 拾光——校园失物招领

“拾光”是 2026 年秋季软件工程课程结对编程项目。它面向校园失物招领场景，提供发布寻物/招领线索、浏览筛选、关键词搜索、查看详情与联系发布者，以及管理本人本地发布记录等功能。

项目使用原生网页技术，不需要安装运行依赖、启动开发服务器或配置数据库。桌面浏览器中采用居中的手机风格布局；项目数据保存在当前浏览器本地，不连接云端服务。

## 项目功能

- **首页浏览：**在寻物信息、招领信息和按最新发布之间切换；信息卡片显示名称、类别、地点、发布时间、类型和状态。
- **组合筛选：**首页可按物品类别和地点关键词筛选，并与寻物/招领/最新发布切换组合。类别与发布表单一致；地点支持部分匹配、去除首尾空白和忽略英文大小写。结果按发布时间倒序，空结果提供清除筛选入口。
- **关键词搜索：**搜索名称、类别、地点和描述，不搜索联系方式或发布者内部标识；支持快捷关键词、回车搜索、重新搜索及空结果提示。
- **发布信息：**发布寻物或招领，填写物品名称、类别、地点、丢失/拾取时间、描述和联系方式。表单会校验必填字段、长度及时间，并在成功后展示初始状态。
- **物品详情与联系方式：**首页、搜索结果和发布成功页均可按物品 ID 打开详情；联系方式在详情弹窗中显示，可尝试一键复制，失败时可手动选择文本复制。
- **我的发布：**查看当前浏览器本地发布者标识对应的记录，按发布时间倒序显示，并筛选全部、进行中或已完成。首页演示记录不属于本人发布。
- **状态更新：**仅从“我的发布”进入本人记录详情后可以发起完成操作；确认后状态持久化，不可撤回。

## 技术栈

- HTML5、CSS3、原生 JavaScript（普通脚本，不使用构建工具或前端框架）
- 浏览器 `localStorage`：保存本地发布记录及本地发布者标识
- Node.js 内置 `node:test`：开发阶段自动化测试；Node.js 不是网页运行依赖
- Google Chrome：项目目标运行浏览器，可直接打开 `index.html`

## 运行环境与启动

网页运行只需要一台可使用 Google Chrome 的电脑。无需安装 npm 依赖，无需启动服务器或配置数据库。

1. 下载或克隆项目仓库：<https://github.com/Lrainnn310/102401601-102401502>
2. 在文件管理器中打开项目目录。
3. 使用 Google Chrome 打开项目根目录中的 `index.html`。
4. 页面显示“拾光——校园失物招领”首页后即可使用。

项目使用相对路径引用 `css/style.css` 与 `js/logic.js`、`js/storage.js`、`js/app.js`，三个脚本按依赖顺序以普通 `<script>` 加载，支持直接通过 `file://` 打开。无需构建步骤。

## 完整使用流程

### 浏览与筛选

1. 在首页选择“寻物信息”“招领信息”或“按最新发布”。
2. 使用“物品类别”下拉框选择类别；选“全部类别”可清除类别限制。
3. 在“地点关键词”中输入地点片段，例如“图书馆”“食堂”或“教学楼”。输入会即时筛选；点击输入框旁的清除按钮可只清除地点条件。
4. 类别、地点和信息类型条件可以叠加。若无匹配结果，可清除类别和地点筛选，或更换条件。卡片点击或键盘 Enter/空格可打开详情。

### 搜索

1. 点击首页右上角搜索按钮进入“搜索物品”。
2. 输入关键词后点击“搜索”或按 Enter；也可点击“水杯”“钥匙”“笔记本”快捷词。
3. 搜索覆盖物品名称、类别、地点和描述，不包含联系方式、`ownerId` 等隐私或内部字段。
4. 选择结果卡片查看详情。搜索页返回入口会尽可能保留关键词、结果及滚动位置。

### 发布寻物或招领

1. 点击底部“发布”导航。
2. 选择“发布寻物”或“发布招领”，填写必填信息后点击“发布信息”。
3. 验证通过并成功写入当前浏览器后会显示发布成功页及初始状态。
4. 可查看详情、继续发布或返回首页。新记录会出现在首页、搜索结果和“我的发布”中。

### 查看详情和联系方式

点击首页、搜索结果或发布成功页中的记录即可查看类型、状态、类别、地点、事件时间、描述及发布时间。点击“查看联系方式”打开当前记录的联系弹窗；如浏览器不允许剪贴板操作，可使用手动选择文本的入口。示例记录没有虚构联系方式，会显示未提供提示。

### 管理“我的发布”及更新状态

1. 点击底部“我的发布”，查看当前浏览器本地发布者标识对应的记录。
2. 选择“全部”“进行中”或“已完成”筛选。
3. 打开本人记录详情，点击完成按钮并阅读二次确认提示。
4. 点击“确认完成”才会写入新状态；“暂不修改”或按 Esc 关闭不会更改记录。

状态转换是单向的：

| 信息类型 | 初始状态 | 完成状态 | 页面操作 |
| --- | --- | --- | --- |
| 寻物（`lost`） | 寻找中（`searching`） | 已找到（`recovered`） | 标记为已找到 |
| 招领（`found`） | 待认领（`pending`） | 已归还（`returned`） | 标记为已归还 |

完成后记录不会删除；首页、搜索结果、“我的发布”和详情会显示更新后的状态。示例数据只能查看，不能更新；已完成记录也不能恢复为进行中。

## 本地数据与限制

- 用户发布记录保存在当前浏览器的 `localStorage`（键 `shiguang.items.v1`），本地发布者标识保存在 `shiguang.owner.v1`。刷新后，同一浏览器中仍可读取这些记录。
- 首页演示数据集中保存在 `js/app.js` 的示例数据中，不作为用户发布写入 `localStorage`；它们不显示在“我的发布”里，也不能更新状态。用户通过表单创建的记录单独保存在本地存储。
- “本人发布”只表示记录的本地 `ownerId` 与当前浏览器保存的标识相符。**项目不需要登录或实名认证，也没有真实账号身份验证**；能访问此浏览器数据的人可能查看或修改本地数据。
- 数据仅保存在当前浏览器，不支持跨设备同步或云端共享。清理浏览器数据、更换浏览器或设备后，记录不会自动迁移。请勿将此演示项目作为线上数据备份。
- 浏览器对 `file://` 页面存储和剪贴板的权限行为可能不同。若本地存储不可用，发布和状态更新可能无法保存；复制失败时可手动复制联系方式。
- 项目不包含后台/数据库、信息编辑或删除、用户登录、实名认证、即时聊天、地图定位和云同步功能。

## 自动化测试与代码检查

页面无需 Node.js。只有运行开发测试时需要安装 Node.js；测试使用内置 `node:test`，没有额外 npm 依赖。测试文件由 `node:test` 注册，可在 PowerShell 中逐个运行整个测试目录：

```powershell
$testFiles = Get-ChildItem tests -Filter '*.test.js' | Sort-Object Name
foreach ($testFile in $testFiles) {
  node $testFile.FullName
  if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
}
```

检查所有 JavaScript 文件语法及差异空白：

```powershell
Get-ChildItem js,tests -Recurse -Filter '*.js' | ForEach-Object {
  node --check $_.FullName
  if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
}
git diff --check
```

当前测试文件共注册 **132 项**：发布/首页交互24项、搜索规则15项、详情与联系方式42项、状态与“我的发布”36项、类别/地点筛选15项。自动化交互测试使用轻量 DOM 和本地存储模拟，不替代真实浏览器、屏幕阅读器或实体手机检查。

## 已知限制

- 数据只存在于当前浏览器本地，无法跨浏览器、跨设备或跨用户同步。

- 剪贴板能力取决于浏览器策略；使用 `file://` 时可能需要改用手动复制。
- 没有真实图片上传、地图定位、即时通讯、后台审核、编辑/删除记录等功能。
- 自动化测试可以验证业务逻辑和模拟交互，但响应式视觉效果及真实辅助技术播报仍需人工检查。
